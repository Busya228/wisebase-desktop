# WiseBase CRM 29.2.1 — обновление исходников

## Статус

Подготовлен комплект исходников поверх неизменённой версии 29.2.0. Это не установщик .exe/.dmg и не опубликованный релиз. Рабочая база, сайт, GitHub и компьютеры сотрудников не изменялись. Проверки выполнялись локально на синтетических данных, без запросов к рабочему Supabase; итог — в QA_RESULTS.md.

## Согласованные правила

- Общая статистика использует все загруженные контакты и предложения, без нового ограничения по владельцу. Существующие настройки чтения и RLS SELECT не изменены.
- Штатный Excel-экспорт менеджера (role=manager) содержит только клиентов с owner_id этого менеджера. Делегированные и ничейные карточки исключаются. Проверка действует и для выбранных клиентов, шаблона и автобэкапа; связанные листы не возвращают исключённые карточки.
- Для администраторов и руководителя подразделения (role=user) прежний полный экспорт сохранён.
- Импорт клиентов требует сети, создаёт записи в Supabase и назначает ответственным вошедшего пользователя. ID и ответственный из файла не используются. Запись считается сохранённой только после ответа сервера с ID.
- Несколько контактных лиц поддерживаются. Собственные дубликаты пропускаются по ИНН, а при отсутствии ИНН у одной из карточек — по компании (для контакта без компании — по имени). Совпадение с чужой карточкой не переносит её менеджеру: может быть создана отдельная собственная карточка.
- Импорт не является одной транзакцией: при ошибке ранее подтверждённые строки остаются в базе. Показывается частичный результат. После обрыва связи перед повтором нужно проверить уже созданные записи, чтобы не получить дубли. Пределы: 10 МБ и 5000 строк на лист; это не полная защита от любых специально сформированных Excel-файлов.
- Старые Excel-выгрузки клиентов/задач поддерживаются. Это не универсальное восстановление всей CRM из резервной копии: предложения, поездки и прочие сущности импортом не восстанавливаются.

## Что ещё исправлено

Экранирование подтверждённых небезопасных полей карточки, проверка схем веб-ссылок, разделение рабочих кэшей и очередей по аккаунтам, остановка устаревших ответов при смене аккаунта, очистка локальной сессии при выходе. Неотправленные операции сохраняются в персональной очереди; ошибки больше не удаляются молча. При неопределённом результате вставки автоматический повтор останавливается до ручной проверки. Усилены Host/навигация/IPC Electron.

Эти меры не заменяют серверную идемпотентность, контроль конфликтов или шифрование данных на диске.

## Перед обновлением

1. На старой версии подключить CRM к сети и дождаться синхронизации очередей у пользователей. Ошибки и неподтверждённые записи проверить отдельно.
2. Сделать резервную копию базы в Supabase и копию текущих исходников/настроек публикации. Excel-экспорт менеджера после обновления — не полная резервная копия всей базы.
3. Не удалять данные приложения, IndexedDB, localStorage, папку профиля Electron или очередь. После обновления незавершённые операции могут оставаться только на исходном устройстве.
4. Прочитать раздел «Что остаётся открытым». Для широкого выпуска рекомендована предварительная проверка серверных рисков из аудита. Сначала провести пилот на тестовой базе или ограниченной группе.

Старые общие кэши и очередь автоматически переносятся только когда локальный профиль подтверждает владельца. Неопознанные данные сохраняются, но не исполняются под новым пользователем. Перенесённая старая очередь требует ручной проверки и подтверждения повтора. Если старые изменения не видны, не очищать хранилище: сохранить профиль устройства и разбирать очередь с администратором.

## Публикация десктоп-обновления

1. Распаковать архив в отдельную папку. Закрыть инструменты, меняющие файлы проекта.
2. Скопировать **содержимое desktop** из архива поверх файлов существующего Git-репозитория **C:\Wisebase** с заменой. Папку .git, локальные настройки Git и необходимые секреты сборки сохранить; .git из архива не требуется. Проверить перенос скрытой папки .github.
3. Не копировать корень всего архива в C:\Wisebase: package.json, main.js, app и publish-update.bat должны лежать непосредственно в C:\Wisebase.
4. Проверить diff перед отправкой: не должно быть чужих несохранённых изменений или секретов. В package.json — 29.2.1, в app/sw.js — wisebase-shell-ver18.
5. Запустить publish-update.bat. Скрипт отправляет изменения в GitHub. Существующий workflow выполняет тесты, собирает Windows/macOS и публикует релиз при успешном завершении. Сам по себе успешный git push ещё не означает успешный выпуск.
6. Проверить GitHub Actions и наличие полного опубликованного релиза. Если версия уже занята, существующий workflow может выбрать другой patch-номер — ориентироваться на фактически выпущенную версию. При ошибке тестов или сборки не обходить проверки.
7. Проверить установку на пилотных Windows/macOS. В этой среде нативные установщики не собирались, автообновление и подпись на реальных ОС не проверялись.

## Веб-версия

Публиковать **web/index.html и web/sw.js вместе** на прежнем хостинге. HTML в web и desktop/app одинаковый; CACHE_NAME обеих копий SW — ver18. Проверить, что сервер отдаёт новые файлы, затем перезапустить вкладку и проверить номер версии. Не очищать данные браузера ради обновления кеша, если есть незавершённые изменения.

## Приёмочная проверка на тестовых данных

- Менеджер A: импортировать небольшую компанию с двумя контактами. После перезагрузки и на другом устройстве проверить, что запись существует в БД и ответственный — A.
- Добавить собственного клиента A, клиента B и клиента без владельца. У A проверить полный/выборочный экспорт, шаблон и автобэкап: только клиент A. Делегирование клиента B не должно включать его в экспорт A.
- Проверить, что статистика A по-прежнему учитывает все доступные общие контакты; у администратора и руководителя подразделения доступен прежний полный экспорт.
- Повторить импорт: собственный дубликат пропускается; чужой владелец не меняется. Проверить отдельно форматы ваших реальных Excel-файлов.
- Проверить отказ записи и обрыв сети: нет сообщения о полном успехе; ранее подтверждённые строки видны, ошибка указана. Не повторять неподтверждённую вставку, пока не проверили базу.
- Выйти из A и войти в B: нет старых карточек/отчётов в памяти, очередь A не отправляется от B. Вернуться в A — незавершённая очередь сохранена. Проверить выход также без сети.
- Ошибочная операция очереди остаётся с причиной; повторять её только после проверки, что запись ещё не выполнена сервером.

## Что остаётся открытым

Нельзя считать все уязвимости закрытыми этим пакетом:

- Реальные RLS, роли, ограничения таблиц, серверный аудит и защита последнего администратора требуют проверки в рабочем Supabase; клиентская правка не доказывает их корректность.
- Авторизация Edge Function crm-push и проверка адресов push endpoint — отдельная серверная работа. Отзыв подписки при выходе сделан best-effort и не заменяет серверную авторизацию.
- Подпись/нотаризация установщиков, защита цепочки обновлений и найденные транзитивные зависимости сборки остаются отдельными задачами.
- Строгая CSP без unsafe-inline, закрепление внешних библиотек и полный повторный аудит всех мест вывода ещё не выполнены.
- Менеджер, которому разрешено читать общие контакты, технически может скопировать их вручную или прочитать через разрешённый API. Ограничение штатного Excel-экспорта не может одновременно разрешать чтение всех данных и гарантировать невозможность их извлечения.

Новых SQL-миграций этот выпуск не добавляет. Существующие SQL-скрипты оставлены для справки/развёртывания, их не нужно вслепую повторно запускать на рабочей базе. Если импорт сообщает об отсутствующих колонках или правах — остановиться и проверить схему/политики, а не ослаблять RLS.

## Откат

Сохранить исходные файлы и базу до пилота. Веб откатывать парой HTML+SW с **новым** именем кеша, чтобы старый SW не удерживал ошибочную версию. Автообновлятор обычно не устанавливает меньшую версию: для десктоп-отката нужен новый релиз с более высоким номером и восстановленным кодом. После отката нельзя удалять персональные очереди 29.2.1; старая версия может их не видеть. Импортированные данные остаются в БД: откат файлов не отменяет импорт, восстановление данных требует отдельного плана.
