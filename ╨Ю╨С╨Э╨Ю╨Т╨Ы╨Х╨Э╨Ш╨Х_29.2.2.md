# WiseBase CRM 29.2.2 — автоматическое обновление даты и данных

## Что исправлено

Причина вчерашней даты: шапка заполнялась только в localInit(), а TODAY рассчитывался один раз при открытии страницы. После полуночи или сна компьютера интерфейс продолжал использовать день запуска.

В 29.2.2:

- Дата и TODAY обновляются в локальную полночь. Дополнительная проверка — каждые 30 секунд, при возвращении в окно/вкладку, после сна и перед действиями пользователя.
- Пересчитываются «Сегодня», просрочки, счётчики задач, сроки визитов и видимые списки. Новая задача/сделка/запись получает актуальную дату; дата, уже введённая в открытой форме, не меняется.
- Календарь переходит в новый месяц, если показывал текущий; выбранный исторический месяц сохраняется.
- Возврат в окно/вкладку и восстановление сети запускают догоняющее чтение данных. Повторяющиеся сигналы объединяются; задержка запуска — примерно 2 секунды, без гарантии времени ответа сервера.
- Пока окно видно, страховочная серверная синхронизация выполняется примерно раз в минуту, помимо существующего Realtime. При недоступном Realtime сохраняется опрос раз в 30 секунд и переподключение.
- Если открыта форма, есть активное поле редактирования/сохранение или неотправленная очередь, фоновый полный снимок откладывается. После завершения редактирования обновление продолжается; застрявшую ошибочную очередь нужно разобрать вручную, а не стирать ради свежих данных.
- Фоновая перерисовка не вызывает повторную навигацию, не сбрасывает выбранную страницу, фильтры и лимиты «Показать ещё». Открытая форма не перезаписывается. Локальная правка или Realtime-изменение, появившееся во время фонового чтения, делает этот снимок устаревшим.
- Выход останавливает таймеры; запоздалый фоновый запрос не продолжает работу от имени нового аккаунта.

Принудительной перезагрузки страницы и перезахода для ежедневного обновления даты не требуется. Браузер может заморозить скрытую вкладку или систему во сне — в таком случае дата исправляется при возвращении. Часы и часовой пояс берутся из настроек устройства; неверные системные часы нужно исправить в ОС.

Это обновление текущего интерфейса/данных, а не тихая установка новых версий программы. Для получения кода 29.2.2 требуется один раз выпустить и применить этот релиз. Рабочие сайт, GitHub и Supabase в ходе подготовки не менялись.

## Выпуск

1. Сделать резервную копию базы и текущих исходников. На старой версии дождаться синхронизации очередей; ошибки проверить отдельно. Не удалять localStorage/IndexedDB или профиль Electron.
2. Архив содержит полный комплект: можно обновляться с 29.2.0 или 29.2.1. Исправления и правила экспорта/импорта 29.2.1 сохранены.
3. Для десктопа скопировать **содержимое desktop** поверх файлов существующего Git-репозитория **C:\Wisebase**, сохранив .git и локальные настройки. Проверить перенос .github. Не вкладывать всю папку архива в C:\Wisebase: package.json, app, main.js и publish-update.bat должны быть непосредственно в корне репозитория.
4. Проверить diff, затем запустить publish-update.bat. Дождаться успешных тестов/сборки GitHub Actions и опубликованного релиза. Номер исходников — 29.2.2; существующий workflow может выбрать другой patch-номер, если эта версия уже занята.
5. Для веба опубликовать **web/index.html и web/sw.js вместе**. Новый кеш — wisebase-shell-ver19. Уже открытая вкладка должна один раз загрузить новый код обычным перезапуском после публикации; старый код не может сам получить отсутствующее в нём исправление.
6. Сначала проверить на пилотном устройстве/тестовой базе, затем распространять. Нативные установщики и доставка автообновления здесь не проверялись.

## Приёмочная проверка

- Оставить CRM открытой на смену дня: дата, «Сегодня» и просрочки должны смениться без F5.
- Свернуть/усыпить устройство, затем вернуться: дата обновляется сразу, при наличии сети начинается догоняющее чтение данных.
- Изменить тестовую карточку с другого устройства: изменение должно появиться через Realtime либо страховочную синхронизацию. Проверять при закрытых формах и без неотправленной очереди.
- Открыть форму с черновиком и своей датой, дождаться смены дня/события обновления: текст и выбранная дата остаются. Закрыть форму — обновление списка продолжается.
- В режиме без сети дата должна меняться, но новые серверные данные появятся только после восстановления связи и обработки очереди.
- У менеджера проверить прежние согласованные правила: статистика общая, Excel — собственные клиенты, импорт — с назначением загрузившего пользователя.

## Проверки и ограничения

Результат полного локального прогона — в QA_RESULTS.md. Новый набор live-refresh проверяет полночь/Новый год, просрочки, календарь, черновики, возврат без сети, фоновую синхронизацию, очередь, параллельные запросы, смену аккаунта и защиту от устаревшего снимка.

Проверки выполнялись в Linux/Chromium с заглушками API и запретом внешних запросов. Реальные RLS/схема Supabase, сетевое поведение рабочей CRM, Windows/macOS, установщики и серверная нагрузка требуют пилота. Интервалы — целевые, а не гарантия в замороженных вкладках или при медленном сервере.

Открытые серверные пункты аудита, push, подпись установщиков, CSP и зависимости не закрыты этим выпуском. Реестр мер 29.2.1 — в ИСПРАВЛЕНИЯ_АУДИТА.md. Подробности предыдущего изменения Excel — в ОБНОВЛЕНИЕ_29.2.1.md. Новых SQL-миграций нет; существующие скрипты не запускать вслепую повторно.

## Откат

Веб откатывать парой HTML/SW с новым именем кеша. Для отката через десктоп-автообновление нужен новый релиз с более высоким номером и восстановленным кодом. Не удалять персональные очереди; файлы приложения не являются резервной копией базы.
