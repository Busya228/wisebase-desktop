WiseBase 29.2.4 — исправление публикации

Что случилось
В исходном пакете новый тест читал JSON планов из ../../plans/, то есть из папки вне desktop-репозитория. При размещении содержимого desktop в корне GitHub-проекта этот путь отсутствует. В изолированной копии воспроизведена ошибка ENOENT. Это ошибка упаковки теста, не ошибка действий пользователя и не изменение рабочих данных. Статус конкретного запуска пользователя нужно сверить в Actions.

Что исправлено
1. Тестовая копия плана помещена в test/fixtures/quarter-plan-seed.json. Тест больше не зависит от соседних папок.
2. Workflow теперь запускает выпуск также при изменении test/**, publish-update.bat и самого workflow. Иначе исправление только тестов могло не запустить новый релиз.
3. publish-update.bat больше не объявляет автоматический выпуск завершенным после одного git push.
4. Добавлены проверки наличия фикстуры внутри репозитория и триггеров workflow. Тесты не отключены и не пропускаются.

Как применить
1. Сохраните копию своей текущей папки проекта.
2. Распакуйте СОДЕРЖИМОЕ этого архива в ту же папку, где находятся ваш publish-update.bat, package.json, app и test. Согласитесь на замену перечисленных файлов. Не создавайте дополнительную вложенную папку.
3. Убедитесь, что test/fixtures/quarter-plan-seed.json существует, а .github/workflows/release.yml заменен. Не удаляйте .git и остальные файлы проекта.
4. Запустите publish-update.bat еще раз. Он отправит исправления; обновленный workflow должен запустить новый выпуск при push в main. Патч сам ничего не публикует до запуска вами.
5. Откройте https://github.com/Busya228/wisebase-desktop/actions и последний Release desktop app. Дождитесь успешного test, обеих сборок build (Windows и macOS) и publish. Одна зеленая Windows-сборка еще не означает завершение всего выпуска.
6. В Releases убедитесь, что релиз опубликован, а не Draft, и есть файлы установщиков/метаданных обновления. Затем откройте в CRM «Проверить обновления». Номер может отличаться от 29.2.4, если workflow назначил номер по счетчику запусков.
7. Если запуск красный — пришлите скриншот упавшего шага и последние строки лога. Не отключайте тесты или проверки сборки. Если все зеленое, но обновления нет, сообщите установленную версию и опубликованный номер релиза.

Этот патч меняет только тесты, workflow и сообщение bat-файла. Он не меняет интерфейс, данные, клиентскую базу или SQL. Миграция квартальных планов и первичный импорт выполняются отдельно по инструкции 29.2.4.

Границы проверки
Исправление проверяется локально в отдельной копии, содержащей только desktop, без папки plans рядом с ней. Это воспроизводит структуру checkout, но не заменяет реальный прогон GitHub Actions на Windows/macOS. Публикация в вашем репозитории из этой сессии не выполняется.
