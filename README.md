# WiseBase CRM — десктоп-версия (Windows/macOS)

Обёртка над веб-версией WiseBase CRM (`index.html` + `sw.js`) на Electron.
Код самого приложения не меняется — десктоп-версия поднимает локальный
веб-сервер на 127.0.0.1 и открывает то же приложение в отдельном окне.
Офлайн-кеш, локальные напоминания о задачах и вход через Supabase работают
так же, как в браузере.

С версии, где добавлен `electron-updater`, приложение умеет **само проверять
и устанавливать обновления** через GitHub Releases этого репозитория
(`Busya228/wisebase-desktop`).

## Быстрый старт (разработка)

```bash
npm install
npm start
```

## Как выпустить обновление (всё автоматически)

1. Положите новую версию CRM в папку `app/` (`index.html`, `sw.js`).
2. Дважды кликните `publish-update.bat` (или вручную: `git add -A`, `git commit -m "..."`, `git push`).

Всё. Версию и теги поднимать не нужно — GitHub Actions
(`.github/workflows/release.yml`) сам присвоит номер (`29.0.N`), соберёт
Windows и macOS, дождётся загрузки всех файлов и опубликует релиз.
Смена «большой» версии — поменяйте `"version"` в `package.json` (например на
`30.0.0`), дальше пойдёт `30.0.N`.

### Как обновляются уже установленные приложения

- Приложение проверяет обновления при запуске и затем каждый час.
- Новая версия скачивается в фоне, затем появляется окно
  «Доступна новая версия приложения. Обновить?»:
  - «Обновить» — перезапуск уже новой версией (~10 сек), без переустановки;
  - «Позже» — напомнит через 4 часа; при выходе из приложения обновление
    применится само.
- Если приложение было свёрнуто в трей — вопрос появится при открытии окна.
- Проверить вручную: значок в трее → «Проверить обновления».

### Важный нюанс про портативную Windows-версию

Автообновление работает только для **инсталлированной** через `nsis` версии
(она же и создаётся в релизе). `portable`-exe остаётся отдельным файлом
без автообновления — он для тех, кто принципиально не хочет ничего
устанавливать; таким пользователям придётся вручную скачивать новую версию
с страницы Releases при каждом обновлении.

### Важный нюанс про macOS и подпись

Сборки сейчас **не подписаны** сертификатом Apple Developer ID. Из-за этого:
- при первом запуске Gatekeeper потребует правый клик → «Открыть»;
- автообновление на реальных Mac может отказаться применять скачанное
  обновление без действительной подписи (Squirrel.Mac проверяет соответствие
  подписи старой и новой версии) — сейчас в этом сценарии стоит проверить это
  на реальном железе после первого релиза. Если это будет мешать, тогда
  нужен платный Apple Developer ID (~$99/год) — дайте знать, помогу подключить
  подпись и нотаризацию в workflow.

Windows-инсталлятор подписывать не обязательно для работы автообновления —
но каждый раз до подписи SmartScreen будет предупреждать «Неизвестный
издатель» на новых установках.

## Первая публикация в этот репозиторий

Если репозиторий `Busya228/wisebase-desktop` ещё пустой, из этой папки:

```bash
git init
git add -A
git commit -m "Initial desktop app"
git branch -M main
git remote add origin https://github.com/Busya228/wisebase-desktop.git
git push -u origin main
git tag v29.0.0
git push origin --tags
```

После пуша тега `v29.0.0` в **Actions** запустится первая сборка — это будет
первый релиз, который смогут скачать пользователи (см. `README-install.md`).

## Структура проекта

- `main.js` — Electron main-процесс: локальный сервер, окно, трей, меню,
  автообновление (`electron-updater`)
- `app/` — файлы веб-приложения (`index.html`, `sw.js`). При обновлении CRM
  просто замените их на новую версию из основного веб-проекта, поднимите
  версию и запушьте тег — дальше по инструкции выше
- `build/` — иконки (`icon.ico`, `icon.icns`, `icon.png`)
- `scripts/afterPack.js` — хук electron-builder: встраивает иконку/версию в
  Windows-exe через чистый JS (`resedit`), без Wine
- `.github/workflows/release.yml` — CI-пайплайн сборки и публикации релизов
